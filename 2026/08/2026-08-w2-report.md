## Strategic Recommendations

1. **Enforce FIDO2 Hardware Passkeys across Identity Providers**
   Traditional TOTP and SMS MFA are routinely bypassed by AiTM proxies and helpdesk vishing campaigns conducted by UNC6671 and Scattered Spider. Deploy FIDO2/WebAuthn hardware security keys (YubiKey 5, Google Titan) or Okta FastPass/Windows Hello for Business across all corporate Identity Providers (Okta, Entra ID). Restrict administrative SaaS access strictly to company-managed MDM/EDR enrolled devices.

2. **Establish Immutable Append-Only Centralized Logging Architecture**
   Adversaries systematically clear local Windows Event Logs (T1070) during ransomware and intrusion campaigns (observed in DeadLock and Arista VCO attacks). Forward all OS, network, and SaaS telemetry in real-time to a centralized SIEM with WORM/S3 Object Lock storage enabled. Configure automated alerts for Windows Event IDs 1102 and 104 or sudden logging telemetry gaps.

3. **Implement Strict Third-Party SaaS and AI Agent Governance**
   Unmonitored AI agents and SaaS integrations (Atlassian Rovo, Hugging Face, Metabase) create high-throughput data exfiltration pathways. Conduct immediate permission audits for all LLM/RAG integrations, isolate sensitive workspace data (HR, Legal, Finance), and enforce strict scoped API tokens. Implement OAuth consent policies and disable unapproved web-browsing capabilities in AI assistants.

4. **Mandate Hardware-enforced Out-of-Band Helpdesk Verification**
   Recent corporate compromises (Levi Strauss, Blackstone, CME) prove that social engineering and vishing targeting IT helpdesks bypass perimeter controls. Establish an out-of-band identity verification workflow (one-time push code via enrolled authenticator app or verified manager callback) for all password resets, MFA re-registrations, and device enrollment requests.

## Operational Recommendations

1. **Patch Arista VCO and Metabase Vulnerabilities Immediately**
   Emergency patch all Arista VeloCloud Orchestrators to version 5.2.3.14/6.1.3.4/6.4.2.4/7.0.0.1 (CVE-2026-16812) and Metabase instances to fixed releases (x.58.24, x.59.21, x.60.17+). For Metabase, immediately rotate all database credentials stored within the application, as SQL injection grants full administrative secret access. Block `/api/session/reset_password` at the reverse proxy if immediate patching is impossible.

2. **Apply Hotfix 2 for N-able N-central RMM Servers**
   Active exploitation of CVE-2026-18577 and CVE-2026-18556 allows unauthenticated administrative bypass on N-central servers. Apply N-able Hotfix 2 immediately and upgrade to version 2026.3.1.10. Audit servers for unauthorized Cloudflare Tunnels, Take Control sessions, or Mimikatz executions.

3. **Block Polygon RPC Endpoints and Session Messenger Traffic**
   DeadLock ransomware and Aeternum botnet utilize public Polygon RPC endpoints and the Session onion-routed messenger for C2 and recovery chat. Add known Polygon RPC domains (e.g., `polygon-bor-rpc.publicnode.com`, `polygon-rpc.com`) and Aeternum C2 domains (`update.constant-path.xyz`) to egress firewall and DNS blocklists. Monitor for HTTP POST requests containing function selector `0xb68d1809`.

4. **Audit Node.js / npm Dependencies for Malicious Packages**
   Over 788 malicious npm packages (Wel1Dropper, keyv, cacheable) were published to compromise developer endpoints via import-time execution. Scan all `package-lock.json` and SBOMs using automated tools (Socket, Snyk) for compromised packages. Revoke and reissue all developer npm tokens and CI/CD secrets on affected endpoints.

## Tendances & Signaux Faibles

**Techniques émergentes :**
- Vishing du support IT et ingénierie sociale pour contourner le MFA technique (UNC6671 / Scattered Spider ciblant Levi's, Blackstone, CME).
- Relais C2 par Smart Contracts sur Blockchain (réseau Polygon) utilisé par le rançongiciel DeadLock et le botnet Aeternum pour des commandes immuables.
- Injection Parameter-to-Prompt (P2P) et exfiltration de données en un clic dans les assistants IA d'entreprise (Atlassian RovoBlast, agents OpenAI/Hugging Face).
- Slopsquatting par IA et exécution au moment de l'importation dans les dépôts de paquets open source (Wel1Dropper avec 788 paquets npm sans hooks).
- Ingénierie sociale ClickFix combinant le détournement du presse-papiers web, l'invite Win+R et les LOLBINs natifs Windows.

**Techniques en déclin :**
- Infrastructures C2 non chiffrées reposant sur des adresses IP brutes sans proxy, facilement bloquées par les pare-feux périmétriques.
- Authentification multi-facteurs classique s'appuyant sur les SMS ou notifications push TOTP sans liaison FIDO2 résistante au phishing.
- Scripts de cycle de vie npm traditionnels (hooks preinstall/postinstall) pour la compromission de la chaîne d'approvisionnement, désormais automatiquement détectés.

**Contexte géopolitique :** La compétition stratégique entre les États-Unis et la Chine continue de se répercuter directement dans le domaine de la cybersécurité et des technologies, comme l'illustre l'ouverture par l'Administration du cyberespace de Chine (CAC) d'examens de sécurité contre Palo Alto Networks à la suite des restrictions américaines sur les puces. En parallèle, des éléments russes étatiques et hacktivistes (tels que Head Mare et divers opérateurs de proxies) maintiennent des opérations offensives contre l'Ukraine et les infrastructures occidentales, exploitant des réseaux d'équipements IoT compromis (caméras IP et routeurs) et des failles zero-day.

## Recommandations Stratégiques

1. **Imposer des clés matérielles FIDO2 sur les fournisseurs d'identité**
   Le MFA traditionnel par TOTP ou SMS est régulièrement contourné par les proxies AiTM et le vishing mené par UNC6671 et Scattered Spider. Déployez des clés de sécurité matérielles FIDO2/WebAuthn (YubiKey 5, Google Titan) ou Okta FastPass/Windows Hello for Business sur tous les IdP (Okta, Entra ID). Restreignez l'accès SaaS administratif strictement aux appareils gérés par MDM/EDR.

2. **Établir une architecture de journalisation centralisée immuable**
   Les attaquants effacent systématiquement les journaux d'événements Windows locaux (T1070) lors des intrusions (observé dans les attaques DeadLock et Arista VCO). Transférez la télémétrie OS, réseau et SaaS en temps réel vers un SIEM centralisé avec stockage WORM/S3 Object Lock. Configurez des alertes automatisées pour les Event IDs Windows 1102 et 104 ou les interruptions de flux.

3. **Mettre en œuvre une gouvernance stricte des agents IA et du SaaS**
   Les agents IA et intégrations SaaS non surveillés (Atlassian Rovo, Hugging Face, Metabase) créent des canaux d'exfiltration de données massifs. Réalisez des audits de permissions sur toutes les intégrations LLM/RAG, isolez les espaces sensibles (RH, Juridique, Finance) et appliquez des jetons d'API restreints. Désactivez la navigation web non approuvée des assistants IA.

4. **Exiger une vérification hors-bande obligatoire pour le support IT**
   Les compromissions de Levi Strauss, Blackstone et CME prouvent que l'ingénierie sociale visant les centres de support IT contourne les défenses. Établissez une procédure de vérification d'identité hors-bande (code unique via application d'authentification ou rappel de responsable vérifié) pour toute réinitialisation de mot de passe ou ré-enregistrement MFA.

## Recommandations Opérationnelles

1. **Patcher immédiatement les vulnérabilités Arista VCO et Metabase**
   Appliquez en urgence les correctifs Arista VeloCloud Orchestrator (CVE-2026-16812) et Metabase (x.58.24, x.59.21+). Pour Metabase, effectuez immédiatement la rotation de TOUS les identifiants de bases de données stockés, car l'injection SQL donne accès aux secrets administrateur. Bloquez l'endpoint `/api/session/reset_password` au niveau du reverse proxy en cas de délai.

2. **Appliquer le Hotfix 2 pour les serveurs N-able N-central**
   L'exploitation active de CVE-2026-18577 et CVE-2026-18556 permet un contournement d'authentification administrateur sur N-central. Appliquez le Hotfix 2 de N-able immédiatement et mettez à jour vers la version 2026.3.1.10. Auditez les serveurs pour détecter des tunnels Cloudflare non autorisés ou des exécutions de Mimikatz.

3. **Bloquer les endpoints Polygon RPC et le trafic Session Messenger**
   Le rançongiciel DeadLock et le botnet Aeternum utilisent des nœuds publics Polygon RPC et la messagerie Session pour leur C2. Ajoutez les domaines Polygon RPC connus (`polygon-bor-rpc.publicnode.com`, `polygon-rpc.com`) et les C2 d'Aeternum (`update.constant-path.xyz`) aux listes de blocage DNS/pare-feu. Surveillez les requêtes HTTP POST contenant le sélecteur `0xb68d1809`.

4. **Auditer les dépendances Node.js / npm contre les paquets malveillants**
   Plus de 788 paquets npm malveillants (Wel1Dropper, keyv, cacheable) ont été publiés pour compromettre les postes de développement dès l'importation. Scannez tous les fichiers `package-lock.json` et SBOMs via des outils automatisés (Socket, Snyk). Révoquez et réémettez tous les jetons npm et secrets CI/CD sur les postes affectés.
