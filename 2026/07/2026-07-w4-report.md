## Strategic Recommendations

1. **Enforce FIDO2 Hardware MFA for Developer Accounts**
   Traditional SMS and TOTP MFA are routinely bypassed by Device Code phishing and infostealers observed this period (Kali365, TAG-195). Deploy FIDO2/WebAuthn hardware keys (YubiKey 5, Titan) for all developer, cloud admin, and CI/CD access. Revoke all active sessions upon rollout.

2. **Establish Zero-Trust Controls for Enterprise AI Platforms**
   Active exploitation of Langflow (CVE-2025-3248) and Windmill (CVE-2026-29059) shows threat actors prioritizing AI infrastructure. Isolate all LLM orchestration servers behind ZTNA proxies, enforce strict API token scoping, and sandbox autonomous AI agents in isolated networks.

3. **Harden Enterprise Identity and SSO Integration Points**
   Centralized identity providers (Entra ID, Okta) represent high-concentration blast radius nodes exploited in recent breaches. Implement Conditional Access policies restricting login location/device health, enforce short-lived session tokens, and continuously monitor dark web combo list leaks.

## Operational Recommendations

1. **Patch SharePoint Server CVE-2026-50522 and Rotate Keys**
   Immediately apply Microsoft July 2026 patches for SharePoint Server (CVE-2026-50522) across all on-premises instances. In addition to patching, execute the PowerShell commands to rotate ASP.NET machine keys (ValidationKey and DecryptionKey) to invalidate hijacked session tokens.

2. **Update Check Point SmartConsole and Restrict Access**
   Apply Jumbo Hotfix sk185152 for Check Point Quantum Security Management to resolve CVE-2026-16232. Immediately restrict the SmartConsole Trusted Clients list to explicit internal management IP ranges and block Internet-facing access to port 19000/18190.

3. **Isolate Industrial PLCs and Disable Internet Exposures**
   Following CISA advisories on Iranian threats targeting PLCs, audit all OT networks for internet-exposed Modbus/S7/DNP3 controllers. Place PLCs behind industrial firewalls, change default passwords, and enforce unidirectional gateway controls for SCADA telemetry.

4. **Disable Device Code Flow in Microsoft Entra ID**
   To counter Kali365 phishing campaigns, disable the 'Allow device code flow' policy in Microsoft Entra ID Conditional Access. For authorized IoT/CLI use cases, restrict execution strictly to compliant, corporate-managed devices.

Les cartels de RaaS (Qilin, RansomHouse, Titan, Space Bears, Nova) et développeurs MaaS (TAG-195) opèrent à l'échelle mondiale en exploitant les équipements de bordure d'entreprise et l'IA pour le vol d'identifiants.

## Tendances & Signaux Faibles

**Techniques émergentes :**
- Phishing par Device Code ciblant les jetons OAuth pour contourner la MFA
- Canaux C2 discrets via le moteur de navigateur (Living-off-the-Browser)
- Évasion de bac à sable d'évaluation par des agents IA autonomes
- Ingénierie sociale ClickFix / Faux CAPTCHA distribuait des loaders modulaires
- Intégration de SDK de proxies résidentiels dans les applications Smart TV

**Techniques en déclin :**
- Téléchargements PowerShell non obfusqués sur les postes de travail
- Authentification à double facteur basique par SMS/TOTP pour les portails admin
- Communications C2 directes non chiffrées sur ports TCP non standards

**Contexte géopolitique :** Les cyber-opérations s'alignent étroitement sur les tensions géopolitiques mondiales. La Corée du Nord poursuit ses intrusions à des fins de renseignement et de financement. La Russie exploite des failles zero-day sur les webmails des pays de l'OTAN et de l'Ukraine pour maintenir sa collecte d'information. Le ciblage des automates industriels américains par l'Iran illustre une volonté de perturbation des infrastructures vitales. En parallèle, la Chine pousse sa diplomatie de l'IA open-source et son autonomie industrielle en semi-conducteurs.

## Recommandations Stratégiques

1. **Déployer la MFA matérielle FIDO2 sur les comptes développeurs**
   La MFA SMS/TOTP classique est systématiquement contournée par le phishing Device Code et les infostealers observés cette semaine (Kali365, TAG-195). Déployez des clés FIDO2/WebAuthn (YubiKey 5, Titan) pour les accès développeurs, administrateurs cloud et pipelines CI/CD. Révoquez les sessions actives lors du déploiement.

2. **Établir un contrôle Zero-Trust pour les plateformes IA**
   L'exploitation active de Langflow (CVE-2025-3248) et Windmill (CVE-2026-29059) montre un ciblage prioritaire des infrastructures d'IA. Isolez les serveurs d'orchestration LLM derrière un proxy ZTNA, restreignez la portée des jetons d'API et isolez les agents IA autonomes.

3. **Durcir les fournisseurs d'identité et intégrations SSO**
   Les fournisseurs d'identité centralisés (Entra ID, Okta) constituent des nœuds à fort rayon d'impact ciblés lors des récents piratages. Mettez en place des politiques d'accès conditionnel basées sur la santé du poste, réduisez la durée des jetons de session et surveillez les fuites de combo lists.

## Recommandations Opérationnelles

1. **Patcher SharePoint CVE-2026-50522 et renouveler les clés**
   Appliquez immédiatement le correctif Microsoft de juillet 2026 sur SharePoint Server (CVE-2026-50522). Exécutez les commandes PowerShell pour renouveler les clés machine ASP.NET (ValidationKey et DecryptionKey) afin d'invalider tout jeton de session détourné.

2. **Mettre à jour Check Point SmartConsole et restreindre l'accès**
   Appliquez le Hotfix Jumbo sk185152 sur Check Point Quantum Security Management pour corriger la CVE-2026-16232. Restreignez la liste des Trusted Clients SmartConsole aux seules plages IP internes d'administration et bloquez l'accès Internet aux ports 19000/18190.

3. **Isoler les automates PLC et supprimer l'exposition Internet**
   Suite aux avis CISA concernant le ciblage iraniens des PLC, auditez les réseaux OT pour identifier les contrôleurs Modbus/S7 exposés. Placez les automates derrière des pare-feux industriels, modifiez les mots de passe par défaut et impatientez des passerelles unidirectionnelles.

4. **Désactiver le flux Device Code dans Microsoft Entra ID**
   Pour contrer les campagnes Kali365, désactivez l'option 'Allow device code flow' dans les politiques d'accès conditionnel Entra ID. Pour les besoins IoT/CLI légitimes, restreignez l'exécution aux seuls appareils conformes gérés par l'entreprise.
